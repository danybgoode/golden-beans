# Wave 2026-08-06 — the signed-in product

The first product wave after two consecutive harness waves. Betting table: the product owner +
the architect agent, run in Cowork off the groomed pitch in
`Roadmap/00-ideas/seeds/app-shell-and-agent-rail.md`.

| Bet | Appetite | Displaced (the opportunity cost) |
|---|---|---|
| **App shell and agent rail** — real section nav over the eleven feature areas, a project-scoped `audit_log` read seam, the agent rail (activity + pending agent proposals) behind `AGENT_RAIL_ENABLED`, and a Command Center front door replacing the bare `<ul>`. Source: the 2026-08-01 `/app` UX audit, P0, narrowed. | M (one wave: architect session + builder fan-out + review rounds) | E4 signals-loop follow-ups and the E6 CMS spike — **a third consecutive park.** The two 2026-08-03 waves each named them as displaced; this makes three. |

**Decisions of record.**

- **M is deliberately smaller than the audit's P0.** As written, P0 was kit adoption across 26
  routes + the agent rail + Command Center + a charting library — an L. Rather than grow the
  appetite, the problem was narrowed: this bet buys the shell, the rail, and a front door that
  answers *"did anything need me today"*, using only primitives already in the repo. The kit sweep
  (`app-component-kit-adoption`) and the charting decision (`analytics-visualization-layer`) are
  separately seeded at `raw`. Appetite as a creative constraint, working as intended.

- **No new runtime dependency.** The `.funnel` / `.bar` CSS is already imported into the signed-in
  app by `globals.css`, and the drift guard asserts that import — so funnel bars need pointing at
  real data, not a library. Whether to add a charting dependency at all is its own decision, and
  likely a spike before a build bet.

- **Propose → confirm: `ConfirmDialog` for owner-initiated actions; staging stays agent-only.**
  This answers audit §8's third open question, narrowed by the verification pass: agent writes over
  the connector *already* all stage (`task_write_confirmations`, credential-bound,
  `CONNECTOR_WRITES_ENABLED`, never enabled in production). An owner confirming their own action a
  second time through a staging table is ceremony, not accountability — the owner *is* the authority
  the staging step defers to. It also keeps the rail's pending list meaningful: everything in it is
  something an agent wants and a human has not yet allowed.

- **Risk HIGH, and not for the UI.** Sprint 1 adds a new tenant-scoped read path over `audit_log`.
  AGENTS rule: no request-derived read path may cross projects. Product owner merges.

- **Kill-switch decided here, not discovered at DoD.** `AGENT_RAIL_ENABLED`, enablement gate ⇒
  default `false`, born OFF, exact `=== 'true'` matching the thirteen existing gates. It gates the
  rail and Command Center's agent strip and explicitly **not** the section nav — a nav that
  disappears with a flag is a worse failure than no flag.

- **Circuit breaker (M lane, hard).** Appetite exhausted ⇒ stop and return to shaping, never extend
  in flight. Most likely trigger, named in the pitch: rail noise scaling with how far propose/confirm
  goes. That decision was taken above precisely to defuse it before a builder starts.

**A debt this wave does not pay, stated so it stays visible.**

E4 signals-loop is marked `status: shipped` but has **not** completed its epic Definition of Done:
`RETROSPECTIVE.md` is still the blank template, `IN-FLIGHT.md` was never deleted, and `sprint-1.md`
reads `⬜ not started` against a README claiming shipped. `BUILD-ORDER.md`'s status-drift advisory
has been reporting this. It is the reason the "E4 follow-ups" this wave displaces could not be found
when asked for — **they were never written.** Closing it out properly is owed work, not new scope,
and it did not fit this wave's appetite. It should be the first candidate at the next boundary.

**Why this was worth a wave.** Two harness waves in a row bought a process that now works and a
plugin that now ships honestly. Neither moved the product. Meanwhile the signed-in app has eleven
feature areas behind a three-link header, zero data visualisation in an analytics product, and an
`AgentWindow` — the device the whole brand promise rests on — that renders only in landing-page
marketing components and never once after sign-in. A PM signs up for "you and your agent" and finds
a `<ul>` of project slugs. That gap between the claim and the screen is the most expensive thing in
the product right now, and it is what this bet buys down.
