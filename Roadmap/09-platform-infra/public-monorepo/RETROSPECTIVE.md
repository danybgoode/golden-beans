## What went well
- **Proving the core bet at the lock.** Before anything was built, a scratch clone showed that
  `git subtree split --prefix=skills` reproduces the mirror's exact `main` (`80d050a`). Every later step leaned on that
  one fact.
- **Measuring the plan's premises killed three bad plans before any code was written**: the seed's `packages/kit`
  layout (it would break the split), the org transfer (Vercel Hobby can't deploy an org-owned repo), and "fix the
  absolute paths" (they were all quotations).
- **Every fresh-reviewer pass found something real.** On #180, a squash merge would have silently broken D1. On #181,
  the skills ruleset would have rejected the first live push. On #182, "only the deploy key can push" was false.

## What we learned
<!-- Promote the durable, generalizable items to Roadmap/LEARNINGS.md (one-liner + why + date). Dedupe. -->
- **Never squash a PR that adds a subtree** (or any PR whose history is the point). A squash flattens the subtree merge,
  so the split roots a new history and the mirror can never fast-forward again. (Promoted.)
- **Check the hosting plan before transferring a repo into an org.** Vercel Hobby won't connect an org-owned repo, and
  "merge = deploy" would have stopped silently. (Promoted.)
- **Never filter a push's output down to its success lines.** A pre-push hook refused a stale board, the filter hid
  it, and a PR comment cited a SHA that never reached GitHub. (Promoted.)
- **A dry run to a scratch branch doesn't exercise the default branch's protections.** The ruleset bypass was first
  tested by the live release.
