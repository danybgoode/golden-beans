gf flags rules — replace a flag’s targeting rules from a file

Usage
  gf flags rules <key> --rules-file rules.json --env production

A FILE, never a command-line expression language. A rule DSL is the appetite trap
  this epic named, and a file has a property that matters more: rules live in source
  control, reviewed, beside the code they target.

  The file is a JSON array of rules. The caps come from the SDK's own constants, so the CLI
  and the parser cannot disagree about how many rules a flag may have.

Flags
  --env <environment>  development | preview | production (repeatable)
  --all-envs           all three environments, under the partial-failure contract
  --project <slug>     the project (default: the remembered one)
  --reason <text>      why — it goes in the audit trail (default: "via gf")
  --rules-file <path>  a JSON array of rules

Exit codes
  0  ok         it worked
  1  usage      the command is wrong — nothing was sent
  2  auth       the credential is not accepted — run `gf login`
  3  not-found  no such thing, or not yours
  4  conflict   someone else changed it — re-read and retry
  5  partial    some environments changed and some did not
  6  server     the server or the network is unwell — retry
