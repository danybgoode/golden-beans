gf flags kill — the 3am verb — serve false, and clear every rule

Usage
  gf flags kill <key> --env production

Two things happen, and the second is the one a hand-composed "set --value false"
  forgets:

    1. the default variant becomes the one whose value is false, AND
    2. EVERY RULE IS CLEARED.

  Without (2) a flag reads as "off" on the flags page while a 10% rollout is still serving
  true to one caller in ten — which is exactly the state you are killing the flag to escape.

  Refuses a non-boolean flag rather than guessing: there is no defensible "off" for a string.

Flags
  --env <environment>  development | preview | production (repeatable)
  --all-envs           all three environments, under the partial-failure contract
  --project <slug>     the project (default: the remembered one)
  --reason <text>      why — it goes in the audit trail (default: "via gf")

Exit codes
  0  ok         it worked
  1  usage      the command is wrong — nothing was sent
  2  auth       the credential is not accepted — run `gf login`
  3  not-found  no such thing, or not yours
  4  conflict   someone else changed it — re-read and retry
  5  partial    some environments changed and some did not
  6  server     the server or the network is unwell — retry
